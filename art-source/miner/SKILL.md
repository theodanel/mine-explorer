## Integration steps

1. Copy the bundle files into a directory your dev server serves over HTTP (Phaser cannot load atlases from `file://`).
2. This is a per-direction character — load ONE atlas per group: `this.load.atlas(key, "spritesheet_<group>.png", "atlas_<group>.json")` for each group listed in `tizo-export.json` → `payload.groups`.
3. Register animations from the atlas's `animations` block — Phaser does NOT auto-create them from the atlas file. For each entry, call `this.anims.create({ key, frames: framesList.map(f => ({ key: atlasKey, frame: f })), frameRate: fps, repeat: loop ? -1 : 0 })`.
4. Add the sprite with any frame from the atlas and play: `this.add.sprite(x, y, atlasKey).play('pickaxe_swing')`.
5. For pixel-art styles set `pixelArt: true` in the game config (or `texture.setFilter(Phaser.Textures.FilterMode.NEAREST)`) so frames don't blur.

// Generic animation registration — works for every bundle, no name guessing.
const atlasData = this.cache.json.get('Petit mineur dragon aventurier-atlas') // load atlas.json separately via this.load.json if needed
for (const [name, def] of Object.entries(atlasData.animations)) {

## Pitfalls

- Frame names inside the atlas are the only valid `frame` values — read them from `atlas.json`, do not assume a `name_0` / `name_0001` pattern.
- Each direction group is a separate texture — switching facing means switching texture key AND playing that group's animation.
